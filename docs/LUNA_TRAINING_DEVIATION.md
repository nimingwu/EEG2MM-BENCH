# LUNA 的训练配方例外：为什么、代价是什么

统一框架的设计不变量是「**只替换 encoder**」，本文件记录一次**有意的例外**：
LUNA 不再使用框架的统一训练配方，改用其论文的微调优化器设置。

这不是协议问题——`DATA_PROTOCOL.md` 第 3 行明确把训练超参排除在协议之外。它破坏的是
**框架自身的一致性**，代价写在 §4，不可淡化。

---

## 1. 统一配方的内容

| | 值 | 定义处 |
| --- | --- | --- |
| 优化器 | `AdamW(model.parameters(), lr=3e-4)`，单一参数组 | `model/atm/training.py` |
| 学习率 | 平坦 `3e-4`，无 warmup、无调度、无裁剪 | 各 `run_*.py` 的 `--atm-learning-rate` 默认值，或调用点字面量 |
| epoch / batch | 40 / 64 | `model/atm/training.py` 的 `DEFAULT_ATM_EPOCHS` / `DEFAULT_ATM_BATCH_SIZE` |
| 种子 | 2000 | `SEED`，协议强制 |

ATM-S（随机初始化）、LaBraM、REVE、LUNA、ENIGMA 全部共用这一套。**正因为配方一致，
encoder 之间的指标差异才能归因于 encoder 本身。**

## 2. 例外

**只有 LUNA 走 `LUNA_OPTIMIZER`（`model/atm/training.py`）。** 其余编码器的代码路径
一行未改（`else` 分支，并有测试钉住）。

| 位置 | 框架统一配方 | LUNA 实际 | 原因 |
| --- | --- | --- | --- |
| 峰值学习率 | `3e-4` | `1e-4` | 论文 Table 6；平坦 3e-4 会塌缩（§3） |
| warmup | 无 | 5 epoch | 论文 Table 6 |
| 调度 | 无 | cosine → `5e-6` | 论文 Table 6 |
| weight decay | AdamW 默认 | `0.05` | 论文 Table 6 |
| layer-wise LR decay | 无 | `0.5` | 论文 Table 6；这是压制残差流漂移的关键 |
| epoch / batch / seed | 40 / 64 / 2000 | **同左，不变** | 把差异限制在优化器，保住「训练预算相同」这一条可比性 |
| 论文另外两项 | — | **未采用**：50 epoch、early stopping | 会改变训练量，破坏预算可比性 |

没有采用「每个 encoder 都用自己的论文配方」这条更彻底的路线，理由见 §5。

## 3. 为什么不得不如此

### 3.1 现象：训练后的 LUNA 是一个常函数

十个 ThingsEEG 被试，40 个 epoch，`top1` 恒为 `0.0050`、`top5` 恒为 `0.0250`——
即**恰好** `1/200` 与 `5/200`。这是并列排序的指纹：200 个测试样本拿到完全相同的
分数，排序只能靠索引打破。

对照组（同一套 seed=2000 流水线）：

| encoder | 测试嵌入的逐维跨样本 std | 十被试 `ssim`（均值 ± 标准差） |
| --- | --- | --- |
| ATM-S | `0.1313` | `0.2194 ± 0.0150` |
| LaBraM | `0.2817` | `0.2106 ± 0.0147` |
| REVE | `0.3741` | `0.2114 ± 0.0178` |
| **LUNA** | **`4.94e-06`** | **`0.2223 ± 0.0003`** |

LUNA 的跨被试标准差比正常模型**小 50 倍**——不是「学得差」，是输出被压成了常数。

**排除 seed**：十个被试的训练损失一致到 5 位有效数字
（`6.874920 / 6.874878 / 6.874869 / …`），十个不同的人、十份不同的 EEG；`top1`/`top5`
又是精确的 `1/N`、`5/N`。seed 只会让结果在随机线附近抖动，做不到这些。

**排除输入归一化**：H5 逐试次逐通道 z-score 正确（std 恰好 `1.000000`、结构性零填充
恰好为 0），与 `luna_input.py` 声明的契约及论文 §4.1 一致。

### 3.2 机制：残差流沿输入无关方向爆炸，末端 LayerNorm 把信号除没了

按层实测（`sub-01`，训练后 vs 预训练）。`DC` = 样本间均值（与输入无关），
`sig` = 样本间标准差（携带刺激信息）：

| | 预训练 DC / sig | 训练后 DC / sig |
| --- | --- | --- |
| block 输入 | `0.37 / 0.36` | `4.30 / 0.222` |
| block 0 | `0.48 / 0.37` | `9.89 / 0.221` |
| block 7 | `1.08 / 0.57` | **`71.26 / 0.218`** |
| 末端 LayerNorm 后 | `0.66 / 0.34` | **`0.67 / 0.0017`** |
| attention pool 后 | `0.25 / 0.077` | `37.39 / 0.00076` |

- **DC 每过一层加约 +8**，从 4.3 线性涨到 71.3（`epoch 5 → 40`：`14.10 → 71.26`）；
  与此同时信号从预训练的 0.36 **掉到** 0.22 且不再变化。
- `LunaBackbone` 是朴素 pre-LN Transformer：残差流上**没有归一化**，只有最后一道
  `LayerNorm`。当 DC 压倒信号时，它除以的是被 DC 支配的尺度，信号被压到 **0.25%**。
- 这是**自增强陷阱**：DC 涨 → LN 增益掉 → 回传梯度趋近零 → 编码器再也无法自救 →
  优化器只剩 DC 和 head bias 可动。塌缩单调进行，不会自行恢复。

**验证**：训练集均值预测器的理论 MSE（`‖y−ȳ‖²/1024`）是 `0.2942`，而下游
`Linear` 投影实测训练 MSE `0.3016` / 测试 `0.2989`——它学到的就是常数预测器。

**为什么只有 LUNA**：微调让 LaBraM 与 REVE 编码器输出的 sig/DC 从 `0.18→2.22`、
`0.44→2.79`（信号绝对值 `0.082→0.837`、`0.646→10.61`），它们学会了用信号；只有
LUNA 从 `0.30` 掉到 **`2.0e-05`**（pooled 输出 `DC 0.25→37.4` 而 `sig 0.077→0.00076`）。

### 3.3 触发器是学习率

从预训练权重出发跑 64 步、扫三个学习率，DC 增长与信息损失都随学习率单调：

| 学习率 | `DC(block 7)` 初始 → 64 步后 | 末端 sig |
| --- | --- | --- |
| `3e-4`（框架统一值） | `1.02 → 5.02` | `0.497 → 0.142` |
| `1e-4`（论文峰值） | `1.02 → 2.86` | `0.497 → 0.184` |
| `3e-5` | `1.02 → 1.93` | `0.497 → 0.248` |

论文 Table 6 的 layer-wise decay `0.5` 使最底层实际只拿到 `~4e-7`，比框架的平坦
`3e-4` **低约 1000 倍**——而 DC 漂移正是底层驱动的。

## 4. 代价（必须随结果一并记录）

**LUNA 行不再是「同配方、不同 encoder」。** 它与其他 encoder 的比较被配方**混淆**：
无法再区分差异来自 encoder 还是来自优化器设置。因此

- LUNA 的数字只能读作「**LUNA 在其官方配方下的参考上界**」；
- **不可与框架内其他 encoder 并列排名**，也不宜用来支持「哪个编码器更好」的结论；
- 用它做消融（如「换个编码器能提升多少」）时，必须把这个例外写进结论的限定条件。

§3 的证据说明这不是「为了好看而调参」——不换配方该行就是随机线，没有信息量。但
**「例外是必要的」不等于「例外不影响可比性」**，两件事都要写。

## 5. 采用与拒绝的备选

| 备选 | 为什么不采用 |
| --- | --- |
| **给全体框架编码器换配方**（保持一致性） | layer-wise decay 对**随机初始化**的 ATM-S 无意义——它会把底层冻住而底层尚未学到任何东西；且 LaBraM/REVE/ENIGMA 在现有配方下本来正常，重跑全部数据集代价翻数倍 |
| **每个预训练编码器各用自己的论文配方** | 最符合「只换 encoder」的**精神**，但 LaBraM 与 REVE 也要重跑并在表里改口径，等于重做整个框架。若将来要彻底消除这个例外，这是正确路线 |
| **冻结 LUNA backbone，只训 pool + head** | 预训练状态下末端 sig/DC = `0.30`，信息完好，代价最小；但同样破坏一致性，且偏离表 3 声称的「整体微调」。仅在 §2 的配方仍不奏效时作为兜底 |
| **维持现状，如实报告 LUNA 为随机线** | 最诚实但最没有信息量：该行不含任何关于 LUNA 能否解码 ThingsEEG 的信息 |

## 6. 溯源

- **LUNA 论文 Table 6（下游微调超参，p.22）**：Peak learning rate `1e-4`；
  Minimal learning rate `5e-6`；Learning rate scheduler `Cosine`；Weight decay `0.05`；
  Total epochs `50`；Early stopping patience `10`；Warmup epochs `5`；
  Drop path `0.1 (B)`；**Layer-wise learning rate decay `0.5 (B)`**。
  （论文预训练 Table 5 用 peak `1.25e-4`、warmup 10 epoch、60 epoch——与之区分。）
- 框架统一配方 `3e-4` 的定义处散布在各 runner 的 `--atm-learning-rate` 默认值与
  `run_nod_reve_luna_benchmark.py:97`、`run_rsvp_atm_seed2000.py:237`、
  `run_nod_atm_pretrained_seed2000.py:86` 的字面量中；`train_atm` 签名默认值为 `3e-4`。
- 层号映射的实现与理由见 `model/atm/training.py:luna_layer_id`。**不能**改用
  `timm.optim.param_groups_layer_decay` 的自动分组：它依赖
  `model.pretrained_cfg['classifier']`，而 `ATMS` 没有该属性，会把全部 211 个参数
  判成「head」塞进同一层，layer scale 退化成常量（已实测，并有回归测试钉住）。

## 7. 怎么用

无需任何额外开关。走 `train_atm` 且 `encoder="luna"` 时自动生效，其余编码器不受影响：

```bash
cd /datas/eeg_benchmark_project/fuxian/fuxian-EEG_Image_decode/EEG2X-Benchmark-v2-test
PYTHONHASHSEED=2000 python3 run_only_clip_linear_seed2000.py \
    run-encoder --encoder luna --subjects sub-01
```

生效时会打一条 INFO，明确告知传入的 `--atm-learning-rate` 被忽略：

```
luna uses its own fine-tuning recipe (lr=0.0001, warmup=5 epochs, cosine to 5e-06,
wd=0.05, layer_decay=0.5) -- the passed learning_rate=0.0003 is ignored.
```

生效后的 LR 阶梯（`sub-01`，×40 epoch）：

| 层 | lr（峰值时刻） | 参数 |
| --- | --- | --- |
| 9（新头） | `1.0e-04` | attention pool / ATM projector / logit_scale |
| 8（block 7） | `5.0e-05` | `backbone.blocks.7.*` |
| 1（block 0） | `3.9e-07` | `backbone.blocks.0.*` |
| 0（输入侧） | `2.0e-07` | patch / freq / 电极位置嵌入、cross-attn |

调度器：第 5 个 epoch 达到峰值 `1e-4`，第 40 个 epoch 落到 floor `5e-6`。

`ATMTrainConfig.optimizer_override` 记录实际生效的设置，随 checkpoint 与 manifest 落盘——
否则产物会谎称用了 `3e-4`。

## 8. 适用范围

**本例外只覆盖 ThingsEEG 的 LUNA 行**（`artifacts/only_clip_linear_seed2000/luna/`）。

其余数据集的 LUNA 行**保留旧配方（平坦 `3e-4`）的结果**，不做例外：

- Grootswager2019（ds004018）、NOD（24 被试）、Grootswagers2025（ds005106，42 被试）；
- 上述三个数据集的 **noise control 列**——仍由旧配方推出（Grootswager2019 是退化模型，
  另两个是塌缩模型），重跑前不应引用。

**ThingsEEG 的 noise control 已随新配方重跑，那一列是有效的**（见 §10.2）。这一点与
上面三个数据集不同，引用时不要混。

### 8.1 试过 Grootswager2019：新配方更差，已回退

2026-10-07 用同一套新配方重跑了 Grootswager2019 的 15 个被试（第 16 个中途停止）。
**结果比旧配方差**：

| 指标 | 旧配方（平坦 `3e-4`） | 新配方（本例外） | 差异 |
| --- | --- | --- | --- |
| clip_similarity | `0.5358` | `0.4988` | **−0.0370** |
| alexnet_2 | `0.5423` | `0.4995` | **−0.0428** |
| inception | `0.5119` | `0.5019` | −0.0100 |
| fid（越低越好） | `297.60` | `314.18` | +16.59 |
| 测试嵌入 per-dim std（均值） | `1.73e-02` | `9.31e-04` | **0.05×** |

**逐被试胜负：新配方更好 4/15，旧配方更好 11/15。**

机制与 §10 的欠训练同源，但在这里跨过了临界点：Grootswager2019 单被试只有 **14400**
个训练试次，是 ThingsEEG（66160）的 **1/4.6**。`layer_decay 0.5` 把主干大部分冻住，
需要足够的数据量才能把可用信息压进剩下的少数层；数据量不够时，冻结的代价超过了它带来
的稳定性。新配方的 per-dim std 在 15 个被试间异常整齐（`8.75e-04 ~ 1.008e-03`，±7%），
旧配方则是 `1.9e-05 ~ 8.2e-02`（跨 4000 倍）——新配方把每个被试都一致地压在了同一个
欠训练状态里。

**对这个例外本身的推论**：它不是「LUNA 需要特殊配方」，而是「LUNA 在**数据量足够**时
需要在低学习率下训练以避免塌缩」。这条阈值没有被量化，是将来若要扩大适用范围时必须先
验证的。

新配方的 15 个被试产物归档在 `artifacts/_luna_recipe_test_grootswagers2019/`，作为这次
负结果的证据；规范路径 `artifacts/grootswagers_luna_atm_sub*_seed2000/` 已恢复为旧配方
结果（16 被试，`0.5332 ± 0.0641`），与原始一致。

### 8.2 为什么 NOD 与 Grootswagers2025 也没有覆盖

不是遗漏，是它们提供不了信息。四个数据集上 LUNA 与同伴的编码器输出离散度（测试嵌入的
逐维跨样本标准差，中位）：

| 数据集 | LUNA | 最好的其他编码器 | 差多少 | 其他编码器解得出来吗 |
| --- | --- | --- | --- | --- |
| ThingsEEG | `6.0e-06` | `0.29` | ~48 600× | 解得出（`0.72–0.74`） |
| Grootswager2019 | `1.4e-03` | `0.12` | ~86× | 解得出（`0.61–0.66`） |
| Grootswagers2025 | `6.7e-04` | `8.5e-02` | ~128× | **解不出**（三个编码器都是 `0.500`） |
| NOD | `2.5e-04` | `1.7e-02` | ~66× | 勉强（`0.50–0.52`） |

**这张表本身是 §3 结论的加强**：LUNA 的表示在四个数据集上一致地比同伴低两个数量级以上，
说明这不是 ThingsEEG 的偶发问题，而是 LUNA 在平坦 `3e-4` 下的固有性质；ThingsEEG 只是
最严重、也最容易观察的一例（因为同数据集的其他编码器真的在解码，差距才显眼）。

注：本表是**中位数**，与 §10 的均值口径不同；两者结论一致，但不要跨表比较数字。

Grootswagers2025 上三个编码器全都落在 `0.500`，修好 LUNA 也改变不了「该数据集在本框架
下解不出信息」的结论；NOD 上最好的同伴也只有 `0.50–0.52`。再结合 §8.1 在 Grootswager2019
上的负结果——那个数据集是**唯一一个既有可测量的差距、又被实测证明新配方会变差的**——
这两处不重跑是**基于收益的判断，不是「它们没问题」的断言**。

## 9. 验证

1. **表示层直接检验**：测试嵌入的逐维跨样本 std 必须从 `4.94e-06` 量级回到 `1e-02` 以上。
2. **语义指标**：四项 2AFC 指标（chance = 0.5000）必须明显脱离随机线。
3. **单元测试**：`tests/test_atm_luna_optimizer.py` 钉住层号映射、LR 阶梯（相邻层恰好
   相差一个 `layer_decay`）、warmup 终点 = 峰值、cosine 终点 = floor、weight decay
   只作用于矩阵、冻结参数被排除、以及「不得退化成单一 scale」的回归守卫。
4. **不回归**：`tests/` 全量通过，非 LUNA 路径的行为不变。

## 10. 实测结果（ThingsEEG，十被试全部完成）

十被试宏平均 ± 样本标准差（ddof=1）：

| 指标 | LUNA 旧（塌缩） | LUNA 新配方 | atm | labram | reve |
| --- | --- | --- | --- | --- | --- |
| 测试嵌入 per-dim std（均值） | `7.05e-06` | **`2.63e-02`** | `1.26e-01` | `2.91e-01` | `3.52e-01` |
| clip_similarity | `0.5001 ± 0.0012` | **`0.5717 ± 0.0439`** | `0.7390 ± 0.0272` | `0.7254 ± 0.0309` | `0.7164 ± 0.0401` |
| alexnet_2 | `0.5001 ± 0.0003` | **`0.5493 ± 0.0200`** | `0.7182 ± 0.0202` | `0.7069 ± 0.0265` | `0.6934 ± 0.0329` |
| inception | `0.4993 ± 0.0031` | **`0.5688 ± 0.0297`** | `0.6994 ± 0.0343` | `0.6769 ± 0.0249` | `0.6740 ± 0.0431` |
| fid（越低越好） | `281.83 ± 6.99` | **`207.03 ± 9.84`** | `184.55 ± 4.91` | `173.82 ± 5.28` | `171.53 ± 4.86` |

逐被试 `clip_similarity`（新）：`0.5766 0.5612 0.5405 0.6343 0.5443 0.5623 0.5533 0.5622
0.5194 0.6629`——**十个全部高于 chance `0.5000`，最低 `0.5194`，无异常个体**。

**塌缩已修复**（两条独立判据同时翻转）：

1. 表示层从 `7.05e-06` 升到 `2.63e-02`（约 3700 倍）；
2. 四项语义指标从 `0.4993–0.5001` 升到 `0.5493–0.6080`，fid 从 `281.83` 降到 `207.03`。

补充判据：跨被试离散度从 `0.0012` 升到 `0.0439`（大 37 倍）。旧版极小的方差本身就是
常函数的证据。`ssim` 同理——从被钉死的 `0.2223 ± 0.0003` 变成 `0.2197 ± 0.0104`。

**但欠训练，且这是可塑性而非训练量的问题。** `test_top1`（sub-01）到 epoch 18–20 才脱离
`0.005`（原框架配方 epoch 4 即脱离），epoch 40 只到 `0.0250`（对照 atm `0.2300` /
LaBraM `0.0950` / REVE `0.0750`）。train loss 在 epoch 13 已到 `8.5791`，到 epoch 40 只降到
`8.1827`——**27 个 epoch 仅改善 4.6%**，已停住。因此增加 epoch 无用；要提升该动的是
`layer_decay`（例如 `0.8`，让最底层拿到 43 倍学习率），但那将偏离论文原值，需另行记录。

**本版本接受欠训练**（用户决策）。§4 的代价因此是实际存在的，不是假想：LUNA 行低于
框架内其他编码器，且不可与它们并列排名。

结果报告见 `../../实验报告12.txt`。

### 10.2 噪声对照（ThingsEEG，十被试）

冻结权重、把测试集 EEG 整段换成 `N(0,1)` 重跑推理，十被试宏平均：
